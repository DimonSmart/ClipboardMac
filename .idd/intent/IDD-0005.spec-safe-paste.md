# IDD-0005.spec-safe-paste

## Intent

Selecting an entry restores it to the system clipboard and performs one safe,
best-effort paste into the field that was active before the history panel
opened. When that cannot be done safely, the product performs Copy Only instead.

## Related Specifications

- IDD-0002 defines suppression of application-originated clipboard writes.
- IDD-0003 defines the exact text of the selected entry.
- IDD-0004 defines Paste and Copy Only user commands.
- IDD-0006 validates the critical behavior on real macOS devices.

## Behavior

- Opening history captures the target application and, when safely available,
  its focused window or element before the panel changes focus. Target identity
  is not recomputed when an entry is selected.
- A paste selection is accepted atomically; while it runs, duplicate selection
  events are ignored. The panel hides, the exact selected text becomes the
  plain-text system clipboard value, and capture synchronizes that self-change.
- The product confirms that the original target can regain focus before sending
  exactly one Command-V key-down/key-up pair. It may activate the target when
  needed.
- Synthetic paste requires Accessibility permission. The product requests it
  transparently and never asks for administrator, screen-recording, or Input
  Monitoring privileges for this MVP.
- If the target ended, focus changed, permission is absent, or target recovery
  is unreliable, the product sends no synthetic input. It leaves selected text
  on the clipboard and reports “Copied. Press Cmd+V to paste”.
- Posting the shortcut is not proof that insertion succeeded. The product does
  not claim success without target feedback and handles protected fields, remote
  desktops, terminal-like applications, and other unsupported targets safely.
- The selected value remains on the clipboard after selection; the prior
  clipboard value is not restored automatically.
- Paste uses the target application's normal paste mechanism for multiline text
  and never simulates each character or executes pasted content itself.

## Product-Significant Architecture And Constraints

- Paste behavior must work with common keyboard layouts, including Russian and
  a non-QWERTY or otherwise alternate layout, without changing selected text.

## Non-goals

- The product does not guarantee a synthetic paste in every target application.
- It does not provide an affirmative pasted-success notification without a
  reliable response from the target.

## Acceptance Criteria

- A click, Enter, double click, or repeated Enter triggers no more than one
  paste operation.
- Losing the target before selection always produces Copy Only and never pastes
  into an unexpected application.
- Copy Only works without Accessibility permission.

## Verification

- Validate paste and fallback behavior in a text editor, browser, code editor,
  terminal-like application, across two keyboard layouts, and while target focus
  is deliberately lost.
