# IDD-0002.spec-clipboard-capture-and-privacy

## Intent

The application captures eligible copied plain text without altering it while
giving users clear privacy controls and respecting macOS clipboard permissions.

## Related Specifications

- IDD-0001 defines product scope and local-data commitments.
- IDD-0003 defines how captured text becomes retained history.
- IDD-0005 defines application-originated clipboard writes during paste.

## Behavior

- Capture observes clipboard changes at a default 500 ms interval without
  overlapping reads. It may miss intermediate changes between observations;
  this is an accepted MVP limitation.
- From a change, capture considers only the first eligible plain-text value. It
  may retain the plain-text representation of formatted copying when one is
  supplied, but ignores items without plain text, images, files, and arbitrary
  combinations of multiple items.
- A captured value is retained byte-for-byte: no trimming or normalization of
  whitespace, line endings, Unicode, case, tabs, or terminal newline. Empty
  text is ignored; whitespace-only text is valid. Text larger than 1 MiB UTF-8
  is ignored without blocking the interface.
- Before reading content, capture excludes clipboard items marked concealed,
  transient, or automatically generated, and may exclude reliably documented
  password-manager markers. Markers are best effort and do not prove content is
  safe when absent.
- Users manage excluded source applications by exact bundle identifier. New
  content attributed to an excluded source is not captured; existing history is
  retained. Exclusion controls capture only, not pasting into that application.
- Capture uses a valid clipboard-provided source identifier first, then a
  best-effort last active application. When the source is unknown, the item may
  be saved without a source identifier and must not be attributed to a guessed
  application.
- Changes made by the application for Copy Only or paste preparation do not add
  history entries and do not suppress later genuine user copies.
- When clipboard access is not allowed, the application avoids repeated system
  prompts, shows Clipboard Access Required with guidance, and does not attempt
  to bypass macOS policy.

## Product-Significant Architecture And Constraints

- Clipboard access must respect the operating system's configured access
  behavior, including ask, always allow, and always deny.

## Non-goals

- Capture does not use a global keyboard hook to eliminate polling gaps.
- It does not promise perfect source attribution for background copies.

## Acceptance Criteria

- Concealed, transient, generated, empty, non-text, and oversized values do not
  create history entries.
- Unicode, emoji, multiline text, whitespace-only text, and a trailing-space
  variant retain their exact distinct values.
- Content from an excluded bundle identifier is not recorded, and denied
  clipboard access does not create a prompt loop.

## Verification

- Verify capture eligibility and exact-text preservation with unit-level
  boundary cases, including race conditions between self-originated and external
  clipboard changes.
- Verify permission behavior on a fresh macOS 26 installation for ask, allow,
  and deny states.
