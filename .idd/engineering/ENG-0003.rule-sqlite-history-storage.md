# ENG-0003.rule-sqlite-history-storage

## Rule

Persist clipboard history with the system SQLite interface, without an ORM, using
versioned migrations, transactions, and prepared parameterized statements.

## Applicability

Conditional

## Applies when

- creating or modifying persisted clipboard-history storage or its migrations

## Rationale

The chosen storage approach supports durable local history, atomic mutations,
and controlled schema evolution without interpolating user-provided text into
SQL.

## Guidance

- Enable WAL behavior and a bounded busy wait suitable for the local database.
- Maintain an explicit schema version and a first versioned migration.
- Use a UUID identity, exact content, its SHA-256 candidate index, creation and
  last-copied times, optional source identifier, and optional pin time.
- Run storage maintenance safely outside normal copy-path latency.

## Verification

Storage review confirms migration versioning, parameterized queries, atomic
history mutations, and cleanup behavior that preserves logical consistency.
